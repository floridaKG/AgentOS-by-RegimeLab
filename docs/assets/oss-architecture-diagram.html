How work runs · tiers & persistence

M-O-E · Mixture of Experts family

Choose the depth you need:

  • 1 Quick — parallel models + judge (fast panels)
  • 2 / 2r Swarm — full agents; read-only audit mode
  • 3 Persistent — multi-round collaborate / redteam with shared transcript

Sidecar · driver + partner

Persistent session — not a one-shot subagent. You reason; the partner executes across turns with shared state. Optional heavy advisor thinks only (no shell).

  • One-shot — fire, answer, done (MOE 1, explorers)
  • Persistent — Sidecar sessions · MOE 3 rounds

Signature moves

Skills Rank → pack → inject

Agents find the skill they need, extract a bounded pack, and load only the context required for the task.

skill-rank→ skill-pack→ context
rtk Rust Token Killer

An efficiency layer that filters and compacts shell output before it reaches the model. Optional — Agent OS works without it.

ls / read / git→ rtk→ thin context
Memory Promote → inject

Capture lessons, promote into long-term search (opt-in backends), inject relevant context next session.

capture→ promote→ inject
Driver pattern One mind · many hands

Configured drivers plan and judge; Sidecar, MOE, and workflows execute. rtk and skill packs reduce context overhead without changing the core.

1 · Memory (always on)

  • SQLite lessons, stumbles, decisions
  • recall search before work
  • write what the session learned
  • inject bounded packet context
capture→ short-term→ promote→ vector / graph

Local SQLite is the core. Connected semantic and graph services are opt-in.

2 · Dispatch (opt-in)

  • ACP agents can hand off tasks
  • Run ledger tracked task records
  • ACPX session transport when configured
  • M-O-E / workflows sit above interchange

Requires agent credentials and configuration.

3 · Skills & protocol

  • skill-rank / pack load on demand
  • M-O-E · Sidecar deliberation & partnership
  • Patterns swarm / council / redteam
  • Specs & gates no unowned SSOT sprawl

Patterns are runnable — not automatic gates.
